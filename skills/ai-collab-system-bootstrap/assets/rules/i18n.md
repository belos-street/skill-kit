# 国际化（i18n）约定

> 本模板以「中英双语、按模块拆分文案」为例。**移植时按目标项目的 i18n 方案改写**；若非双语项目则删除本规则并同步 `AGENTS.md` 规则表。

项目使用 <i18n 库> 实现中 / 英双语。**新增或修改任何用户可见文案时，必须走 i18n，禁止硬编码字符串。**

## 一、目录与文件结构

文案按模块拆分，各语言一份，路径镜像：

```text
{{LOCALE_DIR}}/
├── zh/
│   ├── index.ts          # 注册所有中文模块（命名空间）
│   └── src/<module>.ts   # 中文文案，kebab-case 文件名
└── en/
    ├── index.ts          # 注册所有英文模块（命名空间须与 zh 一致）
    └── src/<module>.ts   # 英文文案，文件名与 zh 完全对应
```

## 二、文案键约定

- **键名直接使用中文文本**，值为对应语言译文：

```ts
// zh/src/audit-log.ts
export default {
  失败原因: '失败原因',
  导出成功: '日志导出成功'
}

// en/src/audit-log.ts（键必须与 zh 完全一致）
export default {
  失败原因: 'Failure Reason',
  导出成功: 'Logs exported successfully'
}
```

- 文件名 → 命名空间映射：`audit-log.ts` 注册为 `auditLog`（camelCase）；注意个别简称例外（如 `vxe-table.ts` → `vxe`）。**以 `index.ts` 中的实际注册名为准。**

## 三、使用方式

通过 `t('命名空间.中文键')` 调用：

```ts
t('auditLog.失败原因')
t('common.编辑')
// 带参数
t('common.长度不超过', { count: 50 })
```

## 四、新增文案检查清单（必须全部满足）

1. **各语言同步**：每种语言的 `<module>.ts` 都要加，且**键名完全一致**，缺一不可。
2. **模块已注册**：若新建模块文件，须在所有语言的 `index.ts` 中都注册同一命名空间。
3. **命名空间正确**：`t()` 的前缀必须与 `index.ts` 注册名一致，否则取不到文案。

## 五、特别注意：缺键不会报错

i18n 配置为 `fallbackLocale` + `missingWarn: false` + `fallbackWarn: false`，**键缺失或命名空间写错时会静默回退/显示键名，不会有任何警告**。因此新增文案后务必人工核对各语言键一致、命名空间正确，避免线上出现未翻译或露出键名。

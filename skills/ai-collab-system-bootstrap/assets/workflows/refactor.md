# Workflow: refactor（重构 / 结构调整）

> 适用：结构调整 / 重构 / 目录迁移 / 技术债清理。由 `workflow-guide.md` 决策表路由。

## 步骤

1. **范围界定** → 明确重构边界与目标（行为不变 / 性能 / 可维护性）；目录迁移遵循「`git mv` 保留历史、对外标识（URL、路由名、公开 API）不变」。
2. **三层文档（spec-first 必走）** → 重构影响面大，**必须**产出 `doc/changes/<change-id>/` 三层文档（影响面清单覆盖所有引用点）并**停下等确认**。
3. **行为不变原则** → 重构不混入功能改动；前后行为等价（必要时先写行为基线用例再重构）。
4. **分步迁移** → 每步独立可验证：迁移一小块 → `{{TYPE_CHECK_CMD}}` 保持绿 → 再下一步。
5. **引用与索引同步** → 路径变更后同步更新：`AGENTS.md` 索引、`doc/architecture/` 指南、`doc/business/` 域文档、rules/workflows 中的交叉引用。
6. **质量验证** → `{{TYPE_CHECK_CMD}} && {{LINT_CMD}}` 保持绿；diff 范围核对（行为不变，无夹带改动）；对 diff 执行 code-review；回归受影响页面冒烟。
7. **决策沉淀** → 结构性结论追加 `decisions.md`；变更记录归档 `doc/changes/`。

## 关键闸门

- 步骤 2 未确认 → 禁止动码；
- 步骤 3 行为不变：diff 中不得出现与重构无关的功能改动。

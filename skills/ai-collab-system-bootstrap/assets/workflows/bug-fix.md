# Workflow: bug-fix（缺陷修复）

> 适用：报障 / 缺陷 / 行为不符 / 测试提 bug。由 `workflow-guide.md` 决策表路由。

## 步骤

1. **复现** → 先复现问题（系统化调试方法）；能写复现用例的先写（TDD 优先）。
2. **定位根因** → 读相关源码 + `doc/business/` 对应域文档「已知坑」 + `git log` 近期变更；区分「数据问题 / 展示问题 / 逻辑问题」。
3. **复杂度判断（spec-first 闸门）** → 修复涉及 3+ 文件或跨模块 → 先出方案等确认；单点修复直接进行。
4. **最小修复** → 只改根因，不扩大范围（不顺手重构、不调整无关样式）；遵循既有编码规范。
5. **回归验证** → 修复点 + 关联展示位（影响面清单）逐一验证；涉及下拉/枚举的检查**所有引用点**。
6. **质量验证** → `{{TYPE_CHECK_CMD}} && {{LINT_CMD}}` 保持绿；改动范围核对（只含根因修复，剔除无关变更）；对 diff 执行 code-review（安全场景用安全审查）。
7. **复盘沉淀** → 新坑补进 `doc/business/` 对应域文档「已知坑」；重要结论追加 `decisions.md`；接口变更先更新 `doc/api`。

## 关键闸门

- 步骤 1 未复现 → 不得动手改码（防盲改）；
- 步骤 4 只允许最小修复，变更行必须全部可追溯到根因。

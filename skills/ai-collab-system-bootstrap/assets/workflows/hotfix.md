# Workflow: hotfix（线上紧急修复）

> 适用：线上紧急问题 / 阻断性故障 / 需立即上线。由 `workflow-guide.md` 决策表路由。

## 步骤

1. **确认紧急程度** → 判断是否真阻断（影响用户数 / 是否可用）；确认可豁免的流程（三层文档、评审等）。
2. **最小修复** → 只做止血改动，禁止夹带重构 / 新功能；优先单点修改。
3. **立即验证** → 修复点直接验证（本地 / 测试环境冒烟），必要时走关键路径自动化。
4. **提交并部署** → Conventional Commits（`fix:` 前缀，标注 hotfix）；按项目部署流程发布。
5. **事后补记录** → 24h 内补齐 `doc/changes/<change-id>/` 三层文档（含线上事故背景、根因、止血 vs 根治）；新坑补进 `doc/business/` 对应域文档；需要根治项的录入待办。
6. **复盘** → 结论沉淀 `decisions.md`；若为流程漏洞触发，反馈到计划/规则层。

## 关键闸门

- 止血改动必须最小：不得在 hotfix 中引入未经验证的行为变更；
- 事后文档补录不可跳过（豁免的是「先行」，不是「补录」）。
